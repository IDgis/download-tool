# Stage 3: Play 2.6 → 2.7 → 2.8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Advance Play from 2.6 to 2.8, replacing the deprecated `WebJarAssets` controller with `WebJarsUtil` across all five controllers and all seven Twirl templates, removing `response().setHeader/setContentType()` calls, and replacing `play.Play.application()` in `layout.scala.html` with injected configuration.

**Architecture:** Two micro-commits on one branch. Play 2.7 (micro-commit 1) is a checkpoint — only the platform version changes; no code changes are needed, and a successful build confirms 2.6 code is forward-compatible. Play 2.8 (micro-commit 2) is the large change: `WebJarAssets` is removed, requiring coordinated updates to all templates and all controllers that pass the asset helper, plus the `response()` mutation API is removed. The `play.Play.application()` call in `layout.scala.html` must also be replaced in this stage (it was deprecated in 2.5 and removed in 2.8).

**Tech Stack:** Gradle 8.8, Play 2.7.9 (intermediate) → 2.8.22, Scala 2.12, Java 8

- [ ] **Step 5: Update `layout.scala.html` — replace `WebJarAssets` and `play.Play.application()`**

`play.Play.application()` is removed in Play 2.8. The template needs to receive configuration as a parameter instead. Full replacement of `web/app/views/layout.scala.html`:

```scala
@(title: String, webJarsUtil: org.webjars.play.WebJarsUtil, config: play.Configuration, jsUrl: String)(content: Html)

@clientConfig() = @{
    config.getConfig(config.getString("download.client"))
}

@displayStatsAnalytics() = @{
    config.getString("display.stats.analytics") == "true"
}

<!DOCTYPE html>
<html>
    <head>
        <meta content="text/html" charset="utf-8">
        <title>@title</title>
        <link href='@webJarsUtil.locate("css/bootstrap.min.css")' rel="stylesheet">
        <link href='@routes.Assets.at("stylesheets/form.css")' rel="stylesheet">
        @if("intern".equals(config.getString("download.access"))) {
            <link href='@routes.Assets.at("stylesheets/form-intern.css")' rel="stylesheet">
        }
        <script src="@webJarsUtil.locate("dojo/dojo.js")" type="text/javascript"></script>
        <script src="@routes.DownloadForm.jsRoutes()" type="text/javascript"></script>
        @if(jsUrl != null) {
            <script src="@jsUrl" type="text/javascript"></script>
        }
    </head>
    <body class='@if(config.getString("deployment.acceptance") == "true") {background-acceptance}'>
        <div class="logo">
            <a href='@clientConfig().getString("url")'>
                <img src='@routes.Assets.at(clientConfig().getString("logo"))' alt="Responsive image"></img>
            </a>
        </div>

        <div class="titlebar">
            <h1 class="header">@title</h1>
        </div>

        @content

        <div class="version">Download-tool: versie @getClass().getPackage().getImplementationVersion()</div>

        @if(displayStatsAnalytics()) {
            <script async src="https://siteimproveanalytics.com/js/siteanalyze_6011273.js"></script>
        }
    </body>
</html>
```

Key changes:
- Parameter `webJarAssets: WebJarAssets` → `webJarsUtil: org.webjars.play.WebJarsUtil`
- New parameter `config: play.Configuration` added
- `routes.WebJarAssets.at(webJarAssets.locate(...))` → `webJarsUtil.locate(...)`
- `play.Play.application().configuration()` removed; `config` parameter used instead
