# Stage 4: Java 8 → 11 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the Java runtime target from 8 to 11 across the build, Docker images, and CI workflow. No Play or application code changes.

**Architecture:** This stage is purely infrastructure. The JVM version is declared in three places: the Gradle play platform, the Docker base images, and the GitHub Actions workflow. All three must be updated atomically. The key risk is that `javax.xml` and `javax.inject` (used throughout the web module) were removed from the JDK in Java 9 but are available via the `play-java` dependencies that bring them as transitive deps — verify they resolve correctly.

**Tech Stack:** Gradle 8.8, Play 2.8.22, Java 11, Zulu JDK 11

### Task 2: Update the Java version in the build

**Files:**
- Modify: `build.gradle`

- [ ] **Step 1: Update the play platform**

Inside `project(':web') { play { platform { ... } } }`:

```groovy
play {
    platform {
        playVersion = '2.8.22'
        scalaVersion = '2.12'
        javaVersion = JavaVersion.VERSION_11
    }
    injectedRoutesGenerator = true
}
```

### Task 3: Update Dockerfiles

**Files:**
- Modify: `build.gradle` (the `createDockerfile` task in `project(':web')`)
- Modify: `build.gradle` (the `createDockerfile` task in `configure([project(':downloader')]`)

The Dockerfile base image is defined inline in `build.gradle` as a task instruction, not in a separate Dockerfile.

- [ ] **Step 1: Update the web Dockerfile task**

In `project(':web')`, find the `createDockerfile` task and change the base image:

```groovy
task createDockerfile(type: Dockerfile) {
    dependsOn copyTar
    destFile = project.file('build/docker/Dockerfile')
    from 'azul/zulu-openjdk:11'    // was: azul/zulu-openjdk:8
    copyFile 'playBinary', '/opt'
    runCommand 'chmod u+x /opt/bin/playBinary'
    exposePort 9000
    defaultCommand '/opt/bin/playBinary'
}
```

- [ ] **Step 2: Update the downloader Dockerfile task**

In the `configure([project(':downloader')])` block, find `task createDockerfile` and change the base image:

```groovy
task createDockerfile(type: Dockerfile) {
    dependsOn copyTar
    destFile = project.file('build/docker/Dockerfile')
    from 'azul/zulu-openjdk:11'    // was: azul/zulu-openjdk:8
    copyFile "${project.name}-${project.version}", '/opt'
    runCommand "chmod u+x /opt/bin/${project.name}"
    defaultCommand "/opt/bin/${project.name}"
}
```

### Task 4: Update the CI workflow

**Files:**
- Modify: `.github/workflows/build-project.yml`

- [ ] **Step 1: Update the java-version field**

In `.github/workflows/build-project.yml`, find the `Set up JDK` step and change `java-version`:

```yaml
      - name: Set up JDK
        uses: actions/setup-java@v4
        with:
          distribution: zulu
          java-version: 11
```

### Task 5: Verify the build and check Java module availability

**Files:** none

- [ ] **Step 1: Run the full build with Java 11**

```bash
./gradlew build
```

Expected: `BUILD SUCCESSFUL`.

- [ ] **Step 2: Verify `javax.xml` and `javax.inject` are still available**

These packages were removed from the JDK in Java 9 but should be provided by the Play dependencies. If the build fails with `package javax.xml.namespace does not exist` or similar, they need to be added as explicit dependencies:

```groovy
// In project(':web') dependencies — only add if needed:
play 'javax.xml.bind:jaxb-api:2.3.1'
```

Spring JDBC (`5.3.39`) and the PostgreSQL driver (`42.7.7`) are both tested on Java 11 — no changes needed there.
