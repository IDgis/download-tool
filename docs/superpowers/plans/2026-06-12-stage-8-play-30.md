# Stage 8: Play 2.9 → 3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Advance Play from 2.9 to 3.0, renaming all `com.typesafe.play.*` imports to `org.playframework.*`, updating group IDs in `build.gradle`, migrating Pekko configuration keys, removing the Typesafe ivy repository, and updating `webjars-play` to the Play 3.0 compatible version.

**Architecture:** Play 3.0 renamed the entire package namespace from `com.typesafe.play` to `org.playframework` and migrated from Akka to Pekko. The import change affects every `.java` and `.scala.html` file in the `web` module that imports any Play type. The Maven artifact group IDs also changed, so all Play dependencies in `build.gradle` need updating. The `application.conf` Akka configuration block (if any) must be renamed to use Pekko keys. This is flagged as the most uncertain stage — verify `org.gradle.playframework` Play 3.0 support before starting.

**Tech Stack:** Gradle 9.x, Play 3.0.x, Scala 2.13 (or Scala 3), Java 17

> **⚠ Flagged 2026-08-05, during Stage 2/3 work:** this plan's `org.webjars.play:webjars-play_2.13:3.0.x` dependency coordinate is probably wrong — verified (during Stage 2/3) that `org.webjars.play` is the Java package name inside the jar, not the real Maven groupId; the actual group has been `org.webjars` at every version checked so far (through 2.8.18). Also, `play-java-ws` has already been renamed once (to `play-ahc-ws`, at Play 2.6) — don't assume `org.playframework:play-java-ws_2.13` is the right artifact name at 3.0 without checking Maven Central first, the same way Stage 2/3 had to for `play-ahc-ws`/`play-guice`. This stage was already flagged by its own author as the most uncertain one (Task 1 is a blocking plugin-support check) — treat every dependency coordinate and version-boundary claim in this plan as needing fresh verification against real jars/Maven Central when you get here, not as given facts.

### Task 4: Rename all `com.typesafe.play.*` imports to `org.playframework.*`

**Files:**
- Modify: `web/app/controllers/DownloadForm.java`
- Modify: `web/app/controllers/DownloadRaster.java`
- Modify: `web/app/controllers/DownloadResult.java`
- Modify: `web/app/controllers/Metadata.java`
- Modify: `web/app/data/MetadataProvider.java`
- Modify: `web/app/ErrorHandler.java`
- Modify: `web/app/util/Cache.java`
- Modify: `web/app/views/*.scala.html` (all template files)

~~Modify: `web/app/controllers/ZooKeeper.java`~~ / ~~Modify: `web/app/DownloadModule.java`~~ — both deleted in Stage 3 (dead code since 2016), don't recreate them here.

The namespace change is mechanical: every `com.typesafe.play` package prefix becomes `org.playframework`. The class names are unchanged.

- [ ] **Step 1: Rename imports in all Java files**

Run this to find all affected import lines:

```bash
grep -rn "com.typesafe.play" web/app/
```

For each file listed, replace `com.typesafe.play` with `org.playframework` in the import lines.

Common renames:
- `import com.typesafe.play.api.*` → `import org.playframework.api.*`
- `import com.typesafe.play.mvc.*` → `import org.playframework.mvc.*`
- `import com.typesafe.play.libs.*` → `import org.playframework.libs.*`
- `import com.typesafe.play.db.*` → `import org.playframework.db.*`
- `import com.typesafe.play.inject.*` → `import org.playframework.inject.*`

Also check for fully-qualified class references in method bodies (not just imports).

- [ ] **Step 2: Rename types in Twirl templates**

Run:

```bash
grep -rn "com.typesafe.play\|play\.api\." web/app/views/
```

In templates, `play.api.UsefulException` → `org.playframework.api.UsefulException` (or `play.api.http.HttpErrorInfo` if that's the current type in `error.scala.html`).

In `layout.scala.html` and other templates, check for any remaining `play.*` type references that map to the old namespace.

- [ ] **Step 3: Verify no `com.typesafe.play` references remain**

```bash
grep -rn "com.typesafe.play" web/app/
```

Expected: no output.

### Task 5: Update `application.conf` — Akka → Pekko configuration keys

**Files:**
- Modify: `web/conf/application.conf`

Play 3.0 uses Pekko internally instead of Akka. Any Akka configuration keys in `application.conf` must be renamed.

- [ ] **Step 1: Check for Akka configuration**

```bash
grep -n "akka" web/conf/application.conf
```

If no Akka keys are present, skip to Task 6.

If Akka keys are present, rename them: `akka.*` → `pekko.*`. Example:
```hocon
# old:
akka.actor.default-dispatcher.fork-join-executor.parallelism-max = 64

# new:
pekko.actor.default-dispatcher.fork-join-executor.parallelism-max = 64
```
